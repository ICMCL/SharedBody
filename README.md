# SharedBody — Paper 26.3 多人控制一个身体

服务端插件 + Fabric 客户端桥接模组，Java 25，Minecraft / Paper **26.3**，SharedBody **1.4.0**。

本 README 说明当前版本的安装、功能和完整命令。各版本的变更与修复见 [CHANGELOG.md](./CHANGELOG.md)。

## 为什么还需要客户端模组

原版客户端不会向服务器发送 F5 切换视角；服务端也不能直接改写另一位玩家客户端的移动输入、背包界面和按键状态。因此本项目不是“原版客户端只装一个插件就能实现全部功能”的方案。

**每位参与者，包括充当身体的玩家，都必须安装配套客户端模组。** 不使用 ProtocolLib、NPC 插件或 NMS 反射。实际身体是一位真实玩家，插件把分工后的输入交给该玩家的客户端执行原版逻辑，其他成员以旁观模式附身观看。

支持多个主体同时运行，每组独立配置九项分工。**每名玩家只能属于一组**，包括已创建但尚未启动的组；每组最多 128 人。

## 安装

1. 服务端使用 Paper 26.3、Java 25。
2. 将 `dist/SharedBody-Paper-26.3.jar` 放入服务器的 `plugins/`，正常重启服务器。不要使用 `/reload`。
3. 每位参与者的 Minecraft 26.3 客户端安装 **Fabric Loader 0.19.5 或更新版本**、**Fabric API 0.163.0+26.3**。
4. 将 `dist/SharedBody-Client-26.3.jar` 放入每位参与者客户端的 `mods/`。
5. 管理员需要 OP 或 `sharedbody.admin` 权限。

两个 JAR 不要放反；Paper 服务端不需要安装 Fabric。没有客户端桥接的普通玩家可以正常游玩，但不能加入正在运行的共享身体。

### 更新现有安装

- 当前桥接协议为 **4**；服务端 1.4.0 与客户端 1.3.0 / 1.4.0 兼容。已使用 1.3.0 客户端时，可只更新 Paper 插件。
- 从 1.2.x 或更早版本升级时，必须同时更新服务端插件和所有参与者的客户端模组。
- 正常停止所有运行中的组和服务器，再替换服务端 JAR。更新客户端前须完全退出 Minecraft，替换后重新启动；不要使用 `/reload`。
- 原有单主体配置会自动迁移到 `state.yml` 的 `groups` 配置节，保留主体、成员、分工和恢复记录。重启不会自动启动旧会话。

### 本机 Game 11 安装

本机安装目标固定为 `/srv/mc-manager/games/11/`，属于 `mcmanager-worker`，普通开发账号没有写权限。先从管理台正常停止 Game 11，再在终端运行：

```bash
bash ~/paper_plugins/sharedBody/install-game11.sh
```

脚本会通过 sudo 请求授权，仅把服务端 JAR 安装到 Game 11 的 `plugins/`，并将 README 和 CHANGELOG 放到
`plugins/SharedBody/`。保持 Worker 用户 / 共享组所有权，校验安装内容；遇到同名旧版本会保留副本，
遇到其他文件名的重复 SharedBody 插件会拒绝安装。不会修改地图模板、其他 Game，也不会自动启动或停止服务器。

安装后在管理台启动 Game 11。若安装时游戏已经运行，需要正常停止并重新启动；不要使用 `/reload`。
客户端模组仍需要发给每位参与者手动安装，不能通过把客户端 JAR 放进服务端来代替。

## 快速开始

假设 Alice 是实际身体，Bob 和 Carol 参与控制：

```text
/sb create Alice
/sb add Alice Bob
/sb add Alice Carol
/sb settings Alice
```

在 GUI 中点击功能，再点击负责该功能的玩家头像。分配好后：

```text
/sb start Alice
/sb status Alice
/sb stop Alice
```

创建时九项功能默认全部交给身体玩家，因此不存在无人负责的空项。每个功能只有一位独占者，同一人可以兼任多个功能，不需要刚好九个人。成员被移除时，其功能回到身体玩家。

## 功能分组

| 独占功能 | 对应操作 |
| --- | --- |
| 视角 | 鼠标转向，上下左右看 |
| 左键 | 攻击、持续挖掘 |
| 右键 | 使用、放置、交互、持续吃东西 / 拉弓等 |
| 背包 | E、物品栏操作、Q / Ctrl+Q 丢弃、数字快捷栏、滚轮 |
| 切换视角 | F5；第一人称 / 后方第三人称 / 前方第三人称同步到所有成员 |
| 副手 | F 交换主副手 |
| 移动 | 前后左右、疾跑；与跳跃、蹲下独立合成 |
| 跳跃 | 空格；也使用原版游泳 / 飞行等语义 |
| 蹲下 | Shift；支持客户端“切换蹲下”设置 |

服从 Minecraft 按键绑定，不强制写死 WASD/E/Q/F/F5。切换疾跑设置也保留。持续按键和按下事件分别同步，支持持续挖掘、右键使用和释放操作，不是简单执行一次交互事件。

**未列出的按键不做独占限制。** 聊天、命令、Tab、F1/F2/F3、截图、全屏等仍由各人操作自己的客户端；鼠标中键 / 选取方块操作不独占，会转发给身体，使用身体当前准星的目标。任意命令不会自动代替身体执行：例如 `/tp` 仍以发出命令的玩家身份执行。

所有动作都作用于身体玩家；生命、饥饿、物品和世界交互结果属于身体，不会复制物品到其他成员的真实背包。经验由身体实际获得，但经验条 / 等级尚未镜像给其他成员。

## 视角与移动

- 视角负责人本地即时更新朝向，不等服务端回包；身体自己负责视角时不会重复叠加转向。
- 朝向独立发送，上限约 60 次/秒；服务端校验唯一负责人和会话后直接转发，不再等待按键合并定时器。实际到达频率仍受客户端帧率、网络和服务器主线程调度影响。
- 身体和其他成员按渲染帧平滑跟随朝向，使用约 25 ms 时间常数，避免原版远程实体旋转插值再叠加一次。第一人称和 F5 两种第三人称都沿用原版镜头位置 / 碰撞逻辑。
- 使用带序号的绝对朝向，不累计旧输入；跨越 ±180° 走最短转角，俯仰限制为 ±90°，高帧率不会无限发送消息。
- 只有视角负责人能改变共享朝向，其他按键的独占规则不变。停止、重新启动会清理旧视角和待发送状态。

- 移动 / 疾跑、跳跃、蹲下使用独立带序号消息；按键变化即发，服务端校验分工后立即转发，身体客户端收到后直接更新输入，不再额外等一次合并输入定时器。
- 实际身体负责的移动功能直接使用本地输入，不等待自己的网络回包；只覆盖自己负责的部分，不覆盖其他人的跳跃或蹲下。
- 镜头位置完全使用原版实体插值和碰撞逻辑，不按行走键预测位移或提前推动镜头。

动作仍在身体客户端执行；攻击 / 放置以身体实际位置和朝向为准。这不会消除网络延迟、低 FPS、低 TPS 或真正的服务器位置纠正。如果身体玩家自己也被拉回，应检查网络、服务器 TPS 及 `moved too quickly` / `moved wrongly` 日志。

## 共享显示

### 物品栏和双手

- 身体玩家继续使用自己的原版物品栏和双手；其他成员默认显示共享快捷栏、选中格、副手槽，以及第一人称身体玩家的手臂和持物模型。F5 仍使用原版第三人称。
- 身体物品快照约每秒检查 10 次，变化即发，并周期重发。只用于显示，不修改旁观成员的真实背包、物品或游戏模式，也不为所有人强制弹出界面。
- 背包负责人以外的旁观成员按 E 可打开共享物品栏的**只读**视图，再按 E 或 Esc 关闭；无法取物、交换、丢弃或发送物品操作。数字键、滚轮、Q 和编辑权限仍只属于背包负责人。
- 背包负责人按 E 打开可操作的远程界面；身体打开箱子等容器时，仍只给负责人发送可编辑界面。其他人可继续移动、转向或观看，不会一起被弹窗。
- 复杂物品动画和地图内容仍依赖原版远程实体 / 地图同步。

### 关闭界面

按 E 打开后，先松开 E，再按 E 即可关闭；Esc 也可关闭。延迟到达的旧菜单快照不会重新打开已关闭的界面。

## 跨维度跟随

切维度前先解除旧旁观目标，切换后重新传送并发送带世界标识、身体实体 ID、递增行程编号的附身目标。客户端等待新世界与正确 UUID 的身体实体就绪，再重设镜头并确认；服务端会重发目标，不能仅凭服务端“已设置旁观目标”认定客户端已经附身。

加载期间持续发送独立心跳，忽略不属于当前已就绪世界的界面 / HUD 快照，并清理旧输入。切维度 / 初次附身有 **600 tick（20 TPS 时约 30 秒）**恢复期限；无法完成附身或传送被拒绝时停止该组并恢复成员，其他组不受影响。

## 共享生存 HUD

- 身体客户端独立发送生存状态，服务端只接受当前身体发布，并转发给所有参与者。约每秒检查 10 次，变化即发；未变化时复用数据包，每半秒重发一次，等待身体实体 / 跨维度加载的成员也能恢复显示。
- 旁观成员使用原版生存 HUD 绘制身体的血量、生命上限、伤害闪烁、金心、护甲、饱食度和氧气。饱和度用于原版饥饿抖动；中毒、凋零、冰冻和饥饿等图标状态也跟随身体。
- 氧气条按原版条件显示：身体眼睛在水中，或氧气尚未恢复满时显示。身体是创造模式时，仍按原版规则隐藏生存条；乘坐生物时保留原版坐骑血条布局。
- 全部是只读显示：不会修改任何参与者真实的血量、饥饿、氧气、效果或游戏模式。实际身体仍使用自己的原版 HUD；未加入共享的玩家不受影响。
- 停止 / 重新分配会话、跟随目标变化和切换世界时清除共享 HUD 缓存；不同会话、错误世界或身体尚未加载完成的数据不会显示。
- 经验条 / 等级等其他 HUD 元素尚未镜像。

## 动态光源与整合包设置

Fabulously Optimized 中的动态光源由 LambDynamicLights 提供。其“第一人称”设置针对本地玩家，不是当前摄像机附身的身体：Alice 是实际身体、Bob 附身观看时，Alice 在 Bob 客户端里仍属于其他实体。

如果 Alice 能看到自己副手物品发光，而 Bob 看不到，先在 **Bob 客户端**的模组菜单中打开 LambDynamicLights 设置，将“动态光源”中的“实体”开启，并保留“第一人称”开启。FO 的部分默认配置为实体关闭、第一人称开启，正好会造成这种差异。

也可以在完全退出 Bob 的 Minecraft 后，编辑该客户端实际游戏目录中的 `config/lambdynlights.toml`，修改现有配置节，不要重复添加：

```toml
[light_sources]
entities = true
self = true
```

重新启动客户端后，在暗处比较 Alice / Bob 的主手和副手光照。此设置只影响本地动态光照显示，不改变服务器方块亮度；不需要修改 Paper 配置、复制物品到 Bob 背包或改变旁观模式。如果启用后仍不生效，需继续核对所用模组版本、玩家实体光源开关及光影配置，不能据此认定所有动态光源模组都兼容。

## 背包远程界面

当背包负责人不是身体玩家时，负责人看到一个通用远程物品栏，而不是自己的背包：

- 同步身体物品栏、装备、副手、2×2 合成格以及打开的容器槽位。
- 支持左右键、Shift 点击、拖动分配、双击收集、数字换位、Q 丢弃、文本输入以及关闭。
- 操作回放到身体客户端的原版容器界面，再由原版服务器验证物品操作，避免服务端直接拷贝背包造成复制漏洞。
- 可见按钮和文本框以简化形式显示；物品提示仍使用原版提示。

**界面边界：** 这是通用槽位 / 控件代理，不是完整复制原版屏幕贴图。熔炉进度、玩家模型、附魔选项的自绘说明、村民交易列表、配方书内部界面等特殊自绘内容没有完整镜像；基础槽位操作可以使用，但不应把复杂特殊界面当成已经完全支持。要使用完整原版特殊界面，应停止共享，在设置中把“背包”交给身体玩家后重新启动。创造模式物品搜索 / 无限物品页也不是远程容器镜像支持范围。

## 多主体示例

创建两组并分别分工、启动：

```text
/sb create Alice
/sb create Dave
/sb add Alice Bob
/sb add Dave Carol
/sb settings Alice
/sb settings Dave
/sb start Alice
/sb start Dave
/sb status
```

各组的输入、视角、背包、HUD 和跟随独立。一组停止、死亡、离线或出错，只影响该组。批量加人、转组及取消创建的具体规则见下方命令说明。

## 命令和权限

完整命令名为 `/sharedbody`，别名为 `/sb`；下面均使用 `/sb`。`<参数>` 必填，`[参数]` 可选，实际输入时不要输入尖括号或方括号。

**主体参数是身体玩家的名字**，不是组内任意成员，也不是 `@a` 等选择器。支持选择器的参数只有 `add` 的加人目标。

除 `create` 和 `status` 外，省略主体时按以下规则选择：

1. 玩家已加入某组：选择自己所在组，即使全服存在多个组。
2. 不属于任何组的玩家或控制台：仅当全服恰好一组时选择该组。
3. 没有组或存在多组且无法确定：报错，不会随意选择。

配置管理权限为 `sharedbody.admin`，默认 OP 拥有。`status` 无权限要求；普通成员只能用 `stop` 停止自己所在组。控制台可执行非 GUI 命令，但 `/sb create` 必须填写玩家名。

| 命令 | 说明 |
| --- | --- |
| `/sb create [玩家]` | 为在线玩家创建独立主体，省略玩家时使用自己；不覆盖已有组 |
| `/sb add [主体] <在线玩家或选择器>` | 批量添加成员，支持 `@a`，跳过并报告其他组成员 |
| `/sb remove [主体] <成员>` | 移除非身体成员，允许按名字移除离线成员，功能回到身体玩家 |
| `/sb settings [主体]` | 打开该组 setting GUI；`setting` / `gui` 也是别名 |
| `/sb start [主体]` | 检查该组成员在线、存活、客户端桥接就绪后启动 |
| `/sb stop [主体]` | 只停止并恢复该组；普通成员只能停止自己组，管理员可指定其他组 |
| `/sb status [主体]` | 不带参数列出全部主体；指定主体查看九项负责人，所有玩家均可用 |
| `/sb dissolve [主体]` | 取消创建、删除已停止且无待恢复记录的该组配置 |

### `/sb create [玩家]`：创建主体

- 权限：`sharedbody.admin`。玩家必须在线；省略时使用执行命令的玩家，控制台不能省略。
- 创建的是以该真实玩家为身体的独立组，不创建 NPC / 假人，也不会覆盖其他组。
- 该玩家不能已经属于任何组，也不能有尚未完成的恢复记录；需先移除原成员身份或删除原组。
- 创建后只有身体玩家一名成员，九项功能默认都交给身体玩家；不会自动启动共享。

```text
/sb create Alice
/sb create
```

第二行表示以自己为身体创建。若要取消创建，使用 `dissolve`。

### `/sb add [主体] <在线玩家或选择器>`：添加成员

- 权限：`sharedbody.admin`。目标组必须停止。
- 完整写法为 `/sb add <主体> <目标>`；省略主体的简写为 `/sb add <目标>`，按前述规则选择组。
- 目标可以是一个在线玩家名，或 `@a`（所有在线玩家）、`@p`（最近玩家）、`@r`（随机玩家）、`@s`（执行者）等玩家选择器。位置相关选择器使用命令执行者的位置；控制台没有玩家实体，`@s` 不会选中玩家。
- 已在本组的不重复添加；其他组成员会被跳过并列出，不会被强制转移。添加不会自动分配控制权，仍需打开 `settings`。
- 每组最多 128 人。超出容量，或待加入的玩家有未完成的恢复记录时，本次添加失败，不会只加入部分成员。
- `@a` 可能包含未装模组的玩家；添加时不检查客户端就绪，启动时会检查。

```text
/sb add Alice Bob
/sb add Alice @a
/sb add Alice @a[distance=..10]
/sb add @a
```

最后一行使用隐式选组；并不表示同时添加到所有组。

### `/sb remove [主体] <成员>`：移除成员

- 权限：`sharedbody.admin`。目标组必须停止。
- 一次移除一个已在本组的非身体成员，按玩家名字匹配；允许移除离线成员，**不支持选择器**。
- 被移除成员负责的功能全部交回身体玩家。不会删除其真实物品或尚待处理的恢复记录。
- 身体玩家不能用 `remove` 移除；删除主体要使用 `dissolve`。

```text
/sb remove Alice Bob
/sb remove Bob
```

转组时，先停止涉及的运行中组，再从来源组移除，加入目标组，并重新分配功能：

```text
/sb remove Alice Bob
/sb add Dave Bob
/sb settings Dave
```

### `/sb settings [主体]`：打开分工 GUI

- 权限：`sharedbody.admin`，只能由游戏内玩家执行。目标组必须停止。
- 点击功能，再点击成员头像选择唯一负责人；同一成员可负责多项，成员较多时支持翻页。
- GUI 标题标明主体，只修改该组；其他组是否运行不影响它。界面中的“启动共享”按钮执行同样的启动检查。
- `setting` 和 `gui` 是子命令别名；不带子命令的 `/sb` 等同于 `/sb settings`。

```text
/sb settings Alice
/sb setting Alice
/sb gui Alice
/sb settings
/sb
```

### `/sb start [主体]`：启动共享

- 权限：`sharedbody.admin`。只启动指定组，其他组不受影响。
- 身体必须在线、存活且不是旁观者；全部成员必须在线、存活、离开载具，并已连接匹配协议的客户端模组。
- 九项功能都必须分配给本组成员，且本组不能有待恢复记录。其他组的待恢复记录不会阻止本组启动。
- 非身体成员的原位置和游戏模式先写入恢复记录，再切换为旁观并附身。启动不会清空或复制背包。

```text
/sb start Alice
/sb start
```

### `/sb stop [主体]`：停止运行，保留配置

- 普通成员可停止自己所在组；停止其他组要求 `sharedbody.admin`。
- 目标组必须正在运行。只停止该组，解除附身，并恢复非身体成员启动前的位置和游戏模式。
- 主体、成员和分工保留，可以再次 `start`。身体玩家保留共享游玩产生的实际位置、物品和状态，不会回档。

```text
/sb stop Alice
/sb stop
```

### `/sb status [主体]`：查看状态

- 所有人和控制台均可使用，不需要管理员权限。
- 不指定主体：列出全服所有组的主体、运行 / 停止状态和成员人数；只有一组时还会列出九项负责人。
- 指定主体：显示该组状态和九项负责人。此命令没有隐式选自己组的规则。

```text
/sb status
/sb status Alice
```

### `/sb dissolve [主体]`：取消创建，删除配置

- 权限：`sharedbody.admin`。目标组必须停止，且组内没有待恢复记录。
- 删除该主体的配置，解除所有成员的组归属；不删除世界、真实玩家或物品，也不影响其他组。
- **与 `stop` 不同：`stop` 保留配置，`dissolve` 删除配置。** 从未启动的组可以直接删除；运行中的组必须先停止。

```text
/sb dissolve Alice
/sb dissolve
```

如果提示还有待恢复玩家，先让相关玩家上线完成恢复，再删除该组。

## 生命周期与运行要求

- 非身体成员暂时成为旁观者，附身跟随身体。其原游戏模式和位置写入 `plugins/SharedBody/state.yml`，退出后恢复；自己的背包保持不变。
- 身体死亡、该组成员退出、客户端桥接报错 / 超时会停止该组，其他组继续运行；插件关闭则停止所有组。身体死亡仍走原版死亡、掉落和复活逻辑。单纯发送过快只限流，不停止共享。
- 身体跨维度时成员重新附身并确认，最长等待 30 秒；被其他插件拒绝传送、篡改旁观者模式或附身失败时会明确停止并提示。
- 未能恢复的离线成员记录会保留，上线时恢复；服务器异常重启不会自动继续旧会话。
- 启动前持久化恢复记录，状态文件采用原子替换；如果世界缺失或状态损坏，插件拒绝启用，不覆盖恢复记录。
- 网络输入丢失超过 5 tick 会松开持续按键；通常桥接超过 60 tick 未响应则停止共享，切维度 / 初次附身的恢复期放宽到 600 tick。消息带会话代号，旧会话数据不能作用到新会话。
- 身体玩家的客户端必须保持运行、在游戏中且不要最小化；打开聊天 / 暂停 / 原版物品栏会受原版屏幕阻止游戏操作的规则影响。
- 旁观者看到所属身体的共享视角、快捷栏、副手、第一人称双手，以及生命 / 饥饿 / 氧气等生存 HUD；经验条 / 等级等其他 HUD 元素仍未镜像。
- 输入有客户端 → 服务端 → 身体客户端的延迟；建议玩家与服务器网络稳定，TPS 保持 20。
- 身体玩家是执行原版动作的可信客户端。这个方案适合协作小游戏，不是防止身体玩家修改模组或作弊客户端的反作弊边界。
- 不修改现有服务器，不会自动安装到正在运行的服务器。

物品栏快照使用压缩，限制为 30 KB 压缩消息 / 1 MB 解压数据；极端物品 NBT 超出限制会明确报错并停止会话，而不是悄悄丢失物品或界面更新。

### 消息限流

每人每服务器 tick 最多处理 40 条桥接消息，超额消息丢弃；下一 tick 重置预算。每人每 100 tick 最多提示 / 记录一次，20 TPS 时约 5 秒。匹配当前会话的有效消息头即使被限流，也会更新活跃时间，**不会仅因发送过快停止共享**。

限流时部分输入可能丢失，持续按键仍有过期释放保护。真实离线、桥接超时、协议错误或恢复失败仍会停止受影响的组。

## 构建

项目使用 Maven。Minecraft 26.3 已采用可直接使用的类名，所以客户端直接针对官方 26.3 JAR 编译，不需要 Yarn、Loom 重映射或在产物中包含 Minecraft 代码。

### 从仓库构建

需要 Java 25 JDK、Maven 3.9+、curl 和提供 `sha1sum` 的 GNU coreutils。普通开发环境先设置 `JAVA_HOME`，并确保 `mvn` 在 `PATH` 中：

```bash
git clone https://github.com/ICMCL/SharedBody.git
cd SharedBody
bash build.sh
```

构建会运行全部模块的自动化测试，生成 `dist/SharedBody-Paper-26.3.jar` 和 `dist/SharedBody-Client-26.3.jar`。可追加 Maven 参数，例如 `bash build.sh --offline`；首次构建仍需要联网下载官方客户端和 Maven 依赖。

仓库只跟踪源码、项目配置和文档，不提交构建产物、Minecraft 客户端 JAR、缓存、运行日志或本机 IDE 文件。`common/` 存放共享协议和输入逻辑，`paper/` 为服务端插件，`client/` 为 Fabric 客户端模组；各模块测试位于自己的 `src/test/` 下。

### 本机共享构建环境

本机原有工作区仍可直接使用：

```bash
cd ~/paper_plugins/sharedBody
bash build.sh
```

Java 构建环境集中在插件工作区中，不需要 sudo：

```text
~/paper_plugins/
├── env/
│   ├── java25/            # Zulu JDK 25，直接包含 bin/java、bin/javac
│   ├── maven/             # Apache Maven 3.9.11，直接包含 bin/mvn
│   ├── maven-repository/  # Maven 依赖和构建插件缓存
│   └── mvn               # 仅对当前命令生效的本地环境入口
└── sharedBody/
```

构建脚本优先调用相邻的 `../env/mvn`，统一选择这里的 JDK、Maven 和依赖缓存，不依赖系统 PATH 中的 Java/Maven，也不向 `~/.m2/repository/` 写入依赖；没有该入口时才使用 `PATH` 中的 `mvn` 和 Maven 默认配置。不修改 shell 配置、系统默认 Java 或生产容器。其他插件项目也可以在自己的项目目录中使用同一个入口：

```bash
bash ~/paper_plugins/env/mvn -version
bash ~/paper_plugins/env/mvn clean verify
```

入口仅在自身进程内设置 `JAVA_HOME` 和 `PATH`，命令结束后不会改变终端环境。首次构建将官方客户端 JAR 下载到临时文件，核对 SHA-1 后才保存为编译缓存；下载中断或校验失败会清理临时文件，不会留下损坏的缓存。客户端 JAR 只安装到所选 Maven 环境的本地仓库用于编译；使用本机入口时为 `env/maven-repository/`，最终两个 JAR 仅包含本项目代码。可再生成的缓存是 Maven 本地仓库、项目 `.cache/` 和各模块 `target/`，JDK 和 Maven 安装目录不是缓存。

测试覆盖九组输入隔离、未分组中键、组合输入、持续输入释放和超时、协议长度 / 非法数据、容器事件编码，以及真实 26.3 客户端的 Mixin 注入点 / 字段和 Fabric ↔ Paper 消息编码兼容性。视角测试额外覆盖本地即时响应、不同渲染帧率下的一致平滑、±180° 跨界、俯仰限制、乱序 / 缺失更新、发送频率上限、停止鼠标后的最终朝向发送，以及会话初始朝向和身份编码。
